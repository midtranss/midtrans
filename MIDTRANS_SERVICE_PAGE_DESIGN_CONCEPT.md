# MIDTRANS Service Page Design Concept

## Purpose

This document defines a visual direction for MIDTRANS service pages. It is design audit output only and does not change any service page.

Service page examples reviewed:

- Services hub `/our-services/`
- Sea Freight `/our-services/seafreight/`
- Customs-related service structures
- Service references across homepage and route pages

## Current Service Page Findings

MIDTRANS service pages contain operationally useful content. The sea freight page, for example, explains:

- FCL and LCL planning
- Documentation review
- Dubai/Jebel Ali relevance
- Syria-related routing
- Customs and inland delivery connection
- Internal links for related planning
- FAQ and final quote CTA

The issue is visual communication. Service pages should look like high-value logistics service pages, not long text pages with repeated sections.

## Main Weaknesses

### 1. Service Hero

Current service heroes communicate service intent but need stronger identity.

Weaknesses:

- Hero lacks a high-impact service visual.
- Transport mode/service category is not visually dominant enough.
- CTA hierarchy could be clearer.
- The page does not immediately show the service process.

### 2. Service Overview

Service overview sections are useful but text-heavy.

Weaknesses:

- Operational details are not broken into enough visual modules.
- Business benefits, geographic coverage, service formats, and operational controls should be visually separated.
- Important document and customs information can blend into body content.

### 3. Internal Links

Internal links are useful but can feel like a list of related pages.

Weaknesses:

- Related links need better card hierarchy.
- Links should be grouped by user intent:
  - quote
  - related service
  - route planning
  - customs/document support
  - platform/track

### 4. FAQ

FAQ content is useful but should be more visually structured.

Weaknesses:

- FAQ cards need cleaner spacing.
- Questions should scan quickly on mobile.
- FAQ should not visually compete with primary CTA.

## Recommended Service Page Structure

### 1. Service Hero

Hero should include:

- Service label
- Clear H1
- 2-line operational summary
- Primary CTA: `Request a Freight Quote`
- Secondary CTA: `Contact MIDTRANS`
- Optional trust badges:
  - Dubai/Jebel Ali operations
  - Customs-aware routing
  - FCL/LCL or relevant mode tags

Visual:

- Service-specific image or illustration
- Example: sea freight container/port visual, air cargo visual, truck/corridor visual, customs document visual

### 2. Service Snapshot Panel

A compact panel under the hero:

- Best for
- Available modes
- Required documents
- Main regions
- Related customs support

This helps users understand service fit quickly.

### 3. Business Benefits Module

Use 3-4 cards:

- Cost control
- Document readiness
- Route feasibility
- Customs coordination
- Delivery scope clarity

Cards should include icons and short text.

### 4. Operational Process

Recommended steps:

1. Cargo facts received
2. Documents reviewed
3. Route and mode selected
4. Customs exposure checked
5. Booking and follow-up
6. Delivery or handover

This should be a horizontal desktop timeline and stacked mobile timeline.

### 5. Documents and Customs Panel

Many MIDTRANS services depend on documents. This should be visually prominent.

Panel content:

- Commercial invoice
- Packing list
- Bill of lading / airwaybill
- Certificate of origin
- HS code direction
- Permits when required

Use a checklist style, not plain paragraphs.

### 6. Related Routes and Services

Use controlled related cards:

- related route
- related service
- customs support
- quote CTA

Each card should have a relevance reason.

### 7. FAQ Section

Use FAQ cards:

- Two columns desktop
- One column mobile
- Clear question typography
- Answer text not too dense

### 8. Final CTA

Service pages should end with:

`Send shipment details for service review`

CTA should ask for:

- origin
- destination
- cargo description
- packages
- dimensions
- weight
- documents if available

## Service Card Style

Recommended:

- White cards
- Thin blue/grey border
- Small service icon
- Strong title
- Short description
- One clear link

Avoid:

- Long paragraphs inside cards
- Too many equal cards in one section
- Repeated generic wording

## Service Hub Direction

The services hub should not be a simple list. It should present MIDTRANS as an integrated service system.

Recommended groups:

1. Freight modes
   - Sea
   - Air
   - Land

2. Customs and documents
   - Customs clearance
   - HS code/document review

3. Logistics support
   - Warehousing
   - Consolidation
   - Packing/loading

4. Special cargo
   - Project cargo
   - Vehicles
   - Cross stuffing

5. Digital support
   - Tracking
   - Platform access
   - Quote workflow

## Mobile Requirements

Service mobile pages should:

- Keep hero short
- Show primary CTA before long content
- Convert process timeline to vertical steps
- Keep document checklist compact
- Avoid overly long related link grids
- Use accordions for FAQs only if schema remains aligned

## Risk Level

Medium.

Service pages are important but less risky than homepage if redesigned one at a time on staging.

## Best Pilot Candidate

A service page such as Sea Freight or Customs Clearance is a good design pilot if not currently protected or if approval names it specifically.

If protected pages must be avoided, create a staging-only service template mockup first.
