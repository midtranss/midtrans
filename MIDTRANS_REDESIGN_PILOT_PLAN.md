# MIDTRANS Redesign Pilot Plan

## Purpose

This document proposes a visual redesign pilot plan. It is planning-only and does not authorize implementation.

The redesign pilot should prove that MIDTRANS can improve visual quality without damaging protected pages, SEO value, content accuracy, schema alignment, or conversion paths.

## Pilot Principle

Do not redesign the whole website at once.

Do not modify live protected pages without explicit approval naming:

- page
- scope
- files
- SEO fields affected
- schema affected
- QA method
- rollback method

## Recommended First Pilot Page

Recommended first pilot page:

`/shipping-from-china-to-syria/`

## Why This Page

This page is a strong pilot candidate because:

- It is strategically important.
- It represents a route/trade lane detail page.
- It contains enough operational content to test visual hierarchy.
- It includes freight modes, documents, customs, related services, CTA, and FAQ.
- It can validate a reusable route page design.

## Risk Level

High.

Reason:

The page is protected and commercially important. Pilot should be staged only until approved.

## Alternative Pilot Options

### Option 1: Non-live static visual prototype

Safest option.

Create a separate prototype file or design mockup that does not replace the live page.

Risk: Low.

### Option 2: Staging-only route page template

Create staging output for `/shipping-from-china-to-syria/` without changing live route.

Risk: Medium.

### Option 3: Service page pilot

Use a lower-risk service page if approved.

Risk: Medium.

### Option 4: Homepage pilot

Not recommended first.

Risk: High because homepage is critical for brand, navigation, SEO, and conversion.

## Pilot Objectives

The pilot should test:

- premium logistics visual identity
- route-specific hero
- origin/destination visual logic
- freight mode tags
- document and customs panels
- operational process section
- related services/cards
- FAQ card layout
- CTA hierarchy
- mobile scanning
- schema-safe FAQ and breadcrumb logic

## Pilot Scope

For the first pilot, redesign only visual structure in staging:

- hero presentation
- route snapshot cards
- document checklist
- customs note panel
- process section
- related service cards
- CTA blocks
- FAQ layout
- mobile spacing

Do not change:

- URL
- title tag
- meta description
- canonical
- hreflang
- robots
- sitemap
- redirects
- FAQ content meaning
- schema meaning
- protected page content without approval

## Phase 0: Visual Audit Confirmation

Before design work:

- confirm current live URL status
- capture current page HTML or screenshot where possible
- record current title/meta/canonical/hreflang
- record current H1
- record visible FAQ
- record schema
- record internal links
- record CTA destinations

No implementation in this phase.

## Phase 1: Wireframe

Create a low-fidelity route page wireframe:

1. Hero
2. Route snapshot
3. Freight mode section
4. Documents and customs panel
5. MIDTRANS operational role
6. Related services
7. FAQ
8. Final CTA

Output:

- Markdown description or static mockup
- No live page replacement

## Phase 2: Visual Mockup

Create a visual mockup using the recommended hybrid design direction.

Required design elements:

- navy/white/blue logistics palette
- route line or corridor visual
- mode tags
- document checklist card
- customs note card
- premium CTA block
- mobile view concept

No live page replacement.

## Phase 3: Staging Build

Only after approval:

- Build staging-only template output.
- Keep approved SEO fields.
- Keep content meaning.
- Keep FAQ/schema alignment.
- Do not deploy live.

## Phase 4: QA

Run QA checklist:

- HTTP 200 in staging
- one H1
- title unchanged unless approved
- meta unchanged unless approved
- canonical unchanged unless approved
- hreflang valid
- visible FAQ matches schema
- breadcrumbs match schema
- internal links work
- CTA works
- no unsupported claims
- no competitor names
- mobile layout clean
- rollback documented

## Phase 5: Approval for Live

Only after stakeholder review:

- compare old and new page
- confirm no SEO/content regression
- confirm mobile behavior
- confirm rollback plan
- receive explicit approval

## Required Deliverables Before Implementation

- Current-state page audit
- Visual wireframe
- Visual mockup
- QA plan
- Rollback plan
- Approved file list

## Success Criteria

The pilot is successful if:

- page looks more premium
- route details are easier to scan
- MIDTRANS looks more serious and international
- quote CTA is clearer
- mobile improves
- SEO fields remain controlled
- schema alignment remains safe
- no live regression occurs

## Recommended Pilot Decision

Ready for visual redesign pilot: **YES, but staging-only and approval-gated**.

Do not start live implementation until approval names the page and allowed scope.
